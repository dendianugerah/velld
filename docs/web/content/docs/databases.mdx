title: Database connections
description: Connect PostgreSQL, MySQL, MongoDB, or Cloudflare D1.

## Add a connection

Open **Connections → Add connection**. Use **Details** or **Connection URL**:

| Engine | Default port | Example URL |
| --- | --- | --- |
| PostgreSQL | 5432 | `postgresql://backup_user:password@db.example.com:5432/shop?sslmode=require` |
| MySQL | 3306 | `mysql://backup_user:password@db.example.com:3306/shop?tls=true` |
| MongoDB | 27017 | `mongodb://backup_user:password@db.example.com:27017/shop?authSource=admin&tls=true` |

Use a host address the **Velld API** can reach. In Compose, `localhost` inside the API container is not the Docker host. Use a database service name on a shared network, or use `host.docker.internal` with the [host-gateway overlay](/docs/installation#enable-docker-features) and a published database port. Match the TLS setting to the server; do not disable TLS for a remote database as a workaround.

Use credentials that can read the objects you need to dump. Restore targets need separate credentials with permission to create and populate objects. MongoDB's authentication database can differ from the database being backed up; set it explicitly if needed.

In the saved connection's **Overview**, use **Choose databases** for multi-database backups. Each database is dumped separately. PITR also requires an explicit database name on the connection.

## Cloudflare D1

Under **Details**, choose **Cloudflare D1**. Enter the Cloudflare account ID, D1 database ID, and an API token with access to database metadata and exports. Velld exports SQL through Cloudflare's API; it does not need a host, port, or SSH tunnel.

D1 restore checks import the export into temporary SQLite and check its integrity, tables, and row counts. Direct restore to D1, branches, schema comparison, and PITR are not available in the dashboard. Download the SQL export for a manual import with Cloudflare's tools.

## Connect over SSH

Expand the SSH settings, enable the tunnel, and enter the jump host, port (usually `22`), and username. Choose password or private-key authentication. The database host and port must be reachable **from the jump host**.

Example: set the SSH host to `jump.example.com:22` (host and port in separate fields), and the database host to `10.0.2.15` with port `5432`. Keep the database credentials in the database fields.

## Discover Docker databases

Enable the [Docker overlay](/docs/installation#enable-docker-features), then open **Connections → Add connection → Docker**. Use **Add & schedule** for a detected container: daily at midnight, with 30 days of retention. Change these in its **Backup schedule** tab. If a container is missing or unreachable, use **Details** with an endpoint the API can reach.
