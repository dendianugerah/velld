## Install with your agent

```text title="Velld install prompt"
Install and verify self-hosted Velld on this machine. Use https://github.com/dendianugerah/velld and read its .env.example and Docker Compose files first.

Use docker-compose.prebuilt.yml for published images, or build docker-compose.yml from the requested Git ref. Keep any existing .env, credentials, and volumes. On a fresh install, generate separate JWT_SECRET and ENCRYPTION_KEY values with openssl rand -hex 32 and set unique admin credentials. Don't print secrets.

Set NEXT_PUBLIC_API_URL to an API URL my browser can reach (default: http://localhost:8080). For local use, bind published ports to 127.0.0.1 in the chosen Compose file. Ask before enabling Docker socket access or remote access. Never delete volumes or connect to production.

Start the stack with docker compose up -d, using -f with the chosen file and --build for a source install. Check Compose status, GET /health, and the web URL. Report how to sign in without printing credentials. Use Bun for JavaScript tasks.
```

## Docker Compose

On a host with Docker Engine or Docker Desktop, Compose v2, Git, and OpenSSL:

```bash
git clone https://github.com/dendianugerah/velld.git
cd velld
umask 077
cp -n .env.example .env
```

Edit `.env` before starting:

| Variable | Value |
| --- | --- |
| `JWT_SECRET` | A random secret for signing sessions. Generate with `openssl rand -hex 32`. |
| `ENCRYPTION_KEY` | Exactly 64 hexadecimal characters. Run `openssl rand -hex 32` again and keep this value with your recovery materials. |
| `ADMIN_USERNAME_CREDENTIAL`, `ADMIN_PASSWORD_CREDENTIAL` | Set both to create a login on first startup. Changing the variables does not reset an existing user's password. |
| `NEXT_PUBLIC_API_URL` | The URL reachable **from your browser**, not the Compose service name. Use `http://localhost:8080` on the same machine or your HTTPS API URL for remote access. |
| `DB_PATH` | Optional SQLite path. Defaults to `/app/data/velld.db` in Compose; keep it in a persistent mount. |
| `RESTORE_CHECK_ENABLED` | Set to `false` to disable automatic restore checks. |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | Optional email settings. Values set in the environment override the corresponding UI settings. |
| `VELLD_PITR_WAL_DIR` | Required only for PostgreSQL [point-in-time recovery](/docs/restore-best-practices#point-in-time-recovery). Set it to the WAL archive mount path inside the API container. |

Put the generated values in `.env`, not the shell command that produced them. Don't commit the file.

```bash
docker compose -f docker-compose.prebuilt.yml up -d
docker compose -f docker-compose.prebuilt.yml ps
curl -fsS http://localhost:8080/health
```

Open [http://localhost:3000](http://localhost:3000) and sign in with the admin credentials you set. The shipped port mappings are not loopback-only. For local-only access, replace the API mapping with `"127.0.0.1:8080:8080"` and the web mapping with `"127.0.0.1:3000:3000"` in your chosen Compose file before starting. Use HTTPS for remote access.

The prebuilt file uses GHCR `latest` images published from the default branch. For features on another Git ref, check out that ref and build both services:

```bash
docker compose up -d --build
```

Both Compose files persist SQLite in `api_data` and backup files in `backup_data`. Back up both volumes and `.env` before updating. Never use `docker compose down -v` on an installation you want to keep.

## Enable Docker features

On a trusted Docker host with `/var/run/docker.sock`, add the discovery overlay **after** your base Compose file:

```bash
docker compose -f docker-compose.prebuilt.yml -f docker-compose.discovery.yml up -d
```

For source builds, use `-f docker-compose.yml -f docker-compose.discovery.yml up -d --build`. Keep the same file flags for later Compose commands. The overlay mounts the socket into the API and adds the Docker host gateway. It enables Docker discovery and lets the API start containers for restore checks, branches, schema comparisons, PG 18 rehearsals, upgrades, and PITR restores.

Docker socket access gives Velld control of the Docker daemon even though the mount is read-only. Leave the overlay off if you don't need these features.

## Local development

Use Bun and Go 1.25 or newer with a C toolchain for SQLite. Install `pg_dump`/`psql`, the MariaDB client tools, or `mongodump`/`mongorestore` locally for the engines you use. The full API image bundles database clients.

From the repository root, with `.env` configured:

```bash
bun install --frozen-lockfile
bun run dev
```

For the docs site alone:

```bash
cd docs/web
bun install --frozen-lockfile
bun run dev --port 3001
```

## Update Velld

Back up the volumes and secrets first. With prebuilt images, use `docker compose -f docker-compose.prebuilt.yml pull`, then repeat your original `up -d` command, including any overlays. With source builds, check out the intended ref and repeat your `up -d --build` command. Check `/health` after restarting.
