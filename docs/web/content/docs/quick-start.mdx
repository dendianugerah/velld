## Run a backup

1. [Install Velld](/docs/installation) and [save a database connection](/docs/databases).
2. Open the connection and choose **Back up now**.
3. Open **History**, check that the backup completed, and open its detail page. The backup status and restore-check result are separate.
4. Download a copy or [test a restore](/docs/restore-best-practices).

## Schedule backups and retention

In the connection's **Backup schedule** tab, enable automatic backups, pick a frequency, and set retention in days. Use the Velld server's time zone, not the browser's.

Custom cron uses **six fields**: second, minute, hour, day of month, month, day of week.

| Cron | Runs |
| --- | --- |
| `0 0 2 * * *` | Daily at 02:00 |
| `0 30 3 * * 0` | Sunday at 03:30 |
| `0 */15 * * * *` | Every 15 minutes |

Retention runs after scheduled backup attempts and applies to completed backups for the connection, including manual backups. The schedule API also supports `retention_count`; if both limits are set, a backup outside either limit can be removed. Enable the connection's object-storage cleanup option if retention should also delete remote copies.

## Store backups off-host

Open **Settings → Storage**, turn on **Object storage**, and choose a provider:

| Field | Amazon S3 example | Cloudflare R2 example |
| --- | --- | --- |
| Provider | S3-compatible | Cloudflare R2 |
| Endpoint and region | `s3.us-east-1.amazonaws.com`, `us-east-1` with TLS enabled | Derived from the 32-character Cloudflare Account ID; Velld uses region `auto` and TLS |
| Bucket name | `team-velld-backups` | `team-velld-backups` (create it in Cloudflare first) |
| Credentials | Bucket-scoped access key ID and secret access key | R2 S3 API token's access key ID and secret access key |
| Path prefix | `production` | `production` |

Use **Test connection**, then save the settings. Run a backup and check **History** and the bucket to confirm upload. A completed backup can still be local if upload failed; check the API logs if you don't see an object.

**Purge local backup after upload** removes the local file after a successful upload. Velld can fetch the remote copy for restores. Leave purging off until you've tested uploads and restores. The bucket stores backup files, not the Velld SQLite database or your encryption key.

## Send failure alerts

Open **Settings → Notifications**. Enable email and enter the recipient and SMTP settings, or enable webhooks and enter a Slack, Discord, or custom webhook URL. Save, then confirm delivery from a controlled failure on a test connection. Velld can send notifications for scheduled backup failures and failed restore checks; it does not send a success message on each backup.
