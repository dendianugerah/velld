title: Troubleshooting
description: Diagnose startup, database client, Docker, storage, and restore failures.
---

## API won't start or login fails

```bash
docker compose -f docker-compose.prebuilt.yml ps
docker compose -f docker-compose.prebuilt.yml logs --tail=100 api web
curl -fsS http://localhost:8080/health
```

Use your own Compose file flags if they differ. For secret errors, replace placeholders with generated values. `ENCRYPTION_KEY` is exactly 64 hexadecimal characters; do not put literal `$(openssl rand -hex 32)` in `.env`. Don't rotate the key to fix startup: the original key is needed to decrypt saved credentials. On a fresh SQLite database set both admin variables. Editing them does not reset a previous login.

If the UI opens but cannot reach the API, check `NEXT_PUBLIC_API_URL` **from the browser's machine**. Don't use `http://api:8080` in a browser or an HTTP API from an HTTPS page. If host ports 3000 or 8080 are taken, change the host-side mapping and update the public API URL if its port changed.

## Docker discovery is empty or the restore check says skipped

Apply [docker-compose.discovery.yml](/docs/installation#enable-docker-features) and verify that `/var/run/docker.sock` exists on the host and is accessible from the API container. The overlay intentionally fails if the socket path does not exist. Check that the database container is running and visible to that daemon. Don't expose the socket over the network.

## The connection works but the dump fails

- **PostgreSQL version mismatch:** Install a compatible `pg_dump` in the API environment (the same or newer major version than the source). Check the version inside the container if using Docker.
- **MySQL unknown option `--skip-ssl`:** Velld uses MariaDB client conventions when TLS is disabled. Use the bundled API image or install MariaDB's client tools instead of substituting Oracle MySQL clients for those commands. For a TLS-enabled server, configure TLS rather than switching it off.
- **MongoDB auth error:** Check `authSource` and that the account can read the selected database.
- **Permission denied:** Test with the same credential and endpoint as the API. A successful login doesn't imply permission to dump all objects.

## Restore fails on a missing role or a nonempty target

- **PostgreSQL `role "…" does not exist`:** A dump may reference roles that are not defined on the target. Verify the intended owners and grants and provision the required roles before retrying a manual restore. Database dumps aren't a backup of cluster-wide roles.
- **Target database must be empty:** Use a newly created database. If a previous attempt left objects behind, don't retry over them or delete objects from a production database.
- **Extension does not exist:** Install the required extension on a suitable target server and retry against a fresh target. Check the **Test on PG 18** report before an upgrade.

## Backup finished but there's no object in the bucket

Use **Settings → Storage → Test connection** with the intended credentials and save the settings. Check bucket permissions and API upload logs. For R2 use the account ID and the S3 API token's access key ID and secret, not a general Cloudflare API token. Confirm that **History** shows object storage before depending on a remote copy.

When reporting an issue, include the Velld image tag or Git ref, database engine and version, and the relevant API or restore-check error. Redact passwords, tokens, and connection strings.
